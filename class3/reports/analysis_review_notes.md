# AI 도서 분석 검토 문답

- 기록일: 2026-11-09
- 대상 보고서: [보고서 초안](report_draft.md)
- 현재 단계: 데이터에서 어떤 특징이 보이는지 살펴보는 탐색적 분석. 기존의 논문-도서 반영 시차 질문은 당장 평가 기준으로 삼지 않는다.
- 기록 목적: 발표의 주장, 분류·해석에 대한 공격, 방어 가능한 범위와 미해결 사항을 보존한다. 이 메모의 논의가 모두 검증되거나 보고서에 반영된 것은 아니다.

## 3.1 분류 기준

### 발표자의 최초 설명

다음 질문을 살펴보기 위해 전체·기술·서비스·일반을 설정했다.

| 항목 | 최초에 알고 싶었던 것 |
|---|---|
| 전체 | 인공지능 관련 책이 얼마나 늘었는가? |
| 기술 | 기술서적은 얼마나 나왔는가? |
| 서비스 | 원천 기술 자체보다 그것을 활용하는 방법을 소개하는 책은 얼마나 나왔는가? |
| 일반 | AI·인공지능 표현은 있으나 성격을 당장 나누기 어려운 책을 모아 볼 수 있는가? |

### 공격

1. **기술명과 기술서의 성격이 같은가?** ‘딥러닝이 바꾸는 사회’ 같은 제목은 기술명에 일치해도 사회·교양서일 수 있다. 반대로 기술명이 직접 드러나지 않는 실습서는 검색에서 빠질 수 있다. 기술명 검출 건수를 기술서 수로 해석할 근거가 부족하다.
2. **서비스명과 활용서의 성격이 같은가?** ‘ChatGPT 업무 활용법’, ‘GPT의 구조와 학습 원리’, ‘ChatGPT가 바꾸는 노동시장’은 비슷한 이름에 일치하지만 책의 목적은 다를 수 있다. 서비스명만으로 활용법 소개 여부를 판별하기 어렵다.
3. **원천 기술과 활용의 경계가 정의되어 있는가?** 딥러닝 실습은 기술 설명이면서 활용일 수 있고, 서비스 API 개발도 기술적일 수 있다. 기술과 서비스는 대상에 관한 구분인데 기술서와 활용서는 설명 목적에 관한 구분이다.
4. **일반이 정말 판정하기 어려운 집단인가?** 현재 규칙은 AI·인공지능 표현의 유무만 판정한다. ‘AI 머신러닝 실전’처럼 기술 분류가 명확한 제목도 일반에 들어간다. 따라서 일반은 분류 불가나 나머지 집단을 뜻하지 않는다.
5. **전체도 사전의 누락과 오탐을 이어받지 않는가?** 세 검색 결과의 합집합이라고 해서 모든 AI 책을 포착했다고 볼 수 없다. 전체 수치 역시 사전과 표기 규칙의 영향을 받는다.

위 책 제목들은 공격의 논리를 설명하기 위한 가상 예시이며 실제 상품 검토 결과가 아니다.

### 방어 가능한 설명

현재 분류는 제목·부제에서 AI를 표현하는 방식에 대한 탐색적 구분으로 사용할 수 있다.

| 항목 | 현재 자료로 방어 가능한 측정 대상 |
|---|---|
| 전체 | 고정된 AI 관련 키워드 사전에 하나 이상 일치한 상품 |
| 일반 | AI·인공지능 같은 포괄적 표현이 있는 상품 |
| 기술 | 특정 AI 기술명이 있는 상품 |
| 서비스 | 특정 AI 서비스·제품·모델명이 있는 상품 |

넓은 분야명, 구체적인 기술명, 특정 제품명이라는 표현 수준을 구분하면 제목에서 어떤 대상을 강조하는지 탐색할 수 있다. 한 제목에 여러 표현이 함께 나올 수 있으므로 독립 플래그와 중복을 허용한다. 모든 연도에는 같은 사전과 검색 규칙을 적용한다.

이 방어는 ‘기술서·활용서·교양서의 수를 정확히 판정했다’는 주장까지 정당화하지 않는다. 키워드 선정의 충분성과 분류 정확성도 별도 검토가 필요하다.

### 재분류에 관한 현재 판단

- 탐색 단계에서 기존 분류값을 전부 폐기하거나 즉시 재분류할 필요는 없다.
- 세 플래그는 키워드 검출 결과로 보존한다. 해당 플래그를 기술서·활용서라는 내용 분류의 대용으로 해석하지 않는다.
- ‘일반=분류 불가·나머지 집단’이라는 설명은 현재 구현과 맞지 않으므로 사용하지 않는다. ‘일반만’도 포괄적 표현은 있지만 현재 기술·서비스 키워드가 검출되지 않았다는 뜻이다.
- 책의 성격을 추가로 구분할지는 분류별 표본과 미검출 표본을 검토해 결정한다. 제목·부제만으로 일관되게 판정 가능한지도 함께 확인한다.
- 현재는 일부 오탐 수정과 집계 일치 검증만 수행했다. 체계적인 표본 검토나 분류 정확도 추정은 아직 수행하지 않았다.

### 다음 확인 사항

1. 실제 표본에서 기술 원리 설명, 사용·실습, 교양·사회 논의가 구별되는가?
2. 그 구분을 제목·부제만으로 일관되게 적용할 수 있는가?
3. 내용 분류가 필요하다면 기존 키워드 플래그와 구별되는 별도 분류로 둘 것인가?

## 기록 작업 검증

- Goal / Reason: 분류 기준 문답과 잠정 판단을 이후 검토에서 다시 사용할 수 있게 보존한다.
- Scope: 이 검토 메모만 추가한다. 보고서·키워드 사전·집계 결과는 변경하지 않는다.
- Acceptance Criteria: 최초 설명, 공격, 방어, 재분류 판단과 미해결 검증을 구분해 기록한다.
- Tests: 대화와의 내용 대조, 보고서 상대 링크와 diff 공백 검사. 문서 변경으로 코드 테스트는 해당하지 않는다.
- Dependencies: 현재 보고서와 분류 기준에 관한 대화.
