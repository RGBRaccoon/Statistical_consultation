# IT·모바일 목록 수집 자료

- Goal: 원격 코드를 통합하고 로컬에서 목록 순회를 완료한 CSV와 체크포인트를 함께 보관한다.
- Reason: 추가 크롤링을 멈추고 현재 자료를 여러 PC에서 활용한다.
- Scope: 목록 CSV, 기존 정상 체크포인트, 자료 설명. 실패한 저장의 임시 파일과 상세 수집은 제외한다.
- Acceptance Criteria: CSV가 파싱되고 상품 ID 중복·손상 행이 없으며 체크포인트의 대기 분류가 없고, 원격 자료의 모든 상품 ID를 포함한다.
- Tests: CSV 전체 파싱, ID 고유성, 행 필드 누락 검사, JSON 파싱 및 현재 분류의 관측 ID가 CSV에 포함되는지 확인했다.
- Dependencies: `../yes24_crawler.py`의 목록 수집 모드.

## 해석 범위

예스24 IT·모바일 및 하위 분류에서 수집기가 탐색한 목록 자료다. 판매지수 순으로 요청하며 분류별 중복을 제거했다.
균형 표본 또는 국내 IT 출판시장 전체로 간주하지 않는다. 발행 연월은 해당 상품의 표시값이며 판매지수는 수집 시점 값으로 실제 판매 부수나 과거 판매 추이가 아니다.
다른 PC로 옮길 때 CSV와 체크포인트를 함께 사용한다. 추가 수집 시 위 건수와 해시 등 보관 상태를 갱신한다.

- 상세 수집은 반복된 HTTP 302 응답으로 중단했다. 전체 도서의 대표 표본이 아니며 완전 수집으로 해석하지 않는다.
- 상세 수집 재개는 목록 CSV가 아닌 상세 CSV와 상세 체크포인트를 함께 사용한다. 실행만으로 남은 목록·상세 요청이 발생할 수 있으므로 재개 의도가 있을 때 실행한다.
- 로그·PID는 Git 추적에서 제외한다. 종료된 실행 흔적과 상세 자료에 포함된 3권 샘플은 정리했으며 통합 전 백업은 로컬에 보존한다.

## 2010년 이후 상세 추가 수집

- 2026-11-13 사용자가 [컬럼·수집 계획](detail_collection_plan.md)을 승인해 [전용 Python 수집기](../yes24_detail_collection.py)로 실행을 시작했다. 대상은 기존 목록의 2010-01~2026-11 상품 27,824건이다.
- `yes24_details_2010_2026.csv`는 승인한 10개 컬럼의 새 상세 자료다. 이전 29개 컬럼 상세 CSV와 섞거나 덮어쓰지 않는다. 진행 중 결과는 전체 완료 자료가 아니다.
- `yes24_details_2010_2026.categories.csv`는 분류 코드·실제 한글명·경로 사전이며, `yes24_details_2010_2026.source_categories.csv`는 기존 목록 출처 코드 14종의 한글명 연결표다.
- [진행 요약](yes24_details_2010_2026.progress.json)에서 완료·확인 필요·실패·미수집 수와 소량 점검 통과 여부를 확인한다. `reused`는 완료/확인 필요 자료 중 기존 상세에서 가져온 건수이며 전체에 중복해서 더하지 않는다.
- 매건 결과와 재개 상태의 원본은 같은 폴더의 `yes24_details_2010_2026.sqlite3`에 있다. CSV·진행 요약은 주기적으로 내보내므로 실제 저장보다 조금 늦을 수 있다. SQLite·잠금·로그는 이 PC에 보관하며 Git에는 포함하지 않는다. 같은 PC에서 같은 명령으로 재개하고, 접근 제한으로 중단된 실행은 원인 확인 없이 재시작하지 않는다.
- 최초 점검 당시에는 96건을 저장해 수동 재개로 인계했다. 이후 사용자가 이어서 수집한 최신 상태와 두 PC 분할은 아래와 같다.

## 두 컴퓨터 분할 수집 — 2026-11-14

- 기존 통합 작업은 저장 후 멈췄다. 1,790건(완료 1,710·확인 필요 80)을 공통 재개 자료 `yes24_details_2010_2026.resume.jsonl`에 담아 원격에 공유한다. 확인 필요 판정과 결측 사유도 보존한다.
- Part 1은 전체 13,930건 중 894건을 가져와 13,036건이 남고, Part 2는 전체 13,894건 중 896건을 가져와 12,998건이 남는다. 명단은 `.part1.targets.csv`와 `.part2.targets.csv`로 확인한다.
- 건별 2~5초·묶음 200~300회·묶음 휴식 3~5분으로 조정했다. 두 파트의 상품 ID는 겹치지 않으며 한 PC에서는 하나의 수집기만 실행할 수 있다.
- 1차 목표는 2010~2016년이다. Part 1은 4,943건 중 4,713건, Part 2는 5,049건 중 4,817건이 남았다. 기본 실행은 2016년까지의 미수집이 없어지면 종료하며, 확인 필요 판정과 이후 연도 자료는 보존한다.
- 두 PC에서 최신 코드를 받은 뒤 각각 `python class3/yes24_detail_collection.py --part 1 --through-year 2016`, `python class3/yes24_detail_collection.py --part 2 --through-year 2016`을 실행한다. 재개할 때도 자기 파트의 명령을 사용한다. 실제 실행은 사용자가 직접 한다.
- 1차 전용 결과는 `.part1.phase1.csv`·`.part2.phase1.csv`이고, 진행 요약의 `phases`에서 각 구간의 건수를 확인한다. 2017년 이후는 두 PC의 1차 결과를 확인한 뒤 `--through-year 2026`으로 같은 저장소에서 이어간다.
- 상세 CSV·진행 요약·분류 사전·운영 SQLite는 모두 `.part1` 또는 `.part2`로 구분한다. 각 PC는 자기 파트의 파일만 갱신한다. 공통 재개 자료는 새 PC 초기화용이며 이미 저장한 파트별 결과를 덮어쓰지 않는다.
- 파트별 `reused`는 기존 통합 자료 또는 이전 상세자료에서 가져온 부분집합이다. `complete`·`review`와 중복해서 더하지 않는다. 완료 후 두 파트 결과를 상품 ID 기준으로 합쳐 전체 대상과 대조한다.
