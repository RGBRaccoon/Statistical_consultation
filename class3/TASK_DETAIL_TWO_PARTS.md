# Task: 수집 간격 재조정과 두 컴퓨터 분할 실행

- Goal: 건별 2~5초·200~300회 묶음·3~5분 휴식으로 조정하고, 겹치지 않는 두 파트와 기존 결과를 원격 저장소에 배포한다.
- Reason: 약 36시간의 수집 목표를 위해 두 컴퓨터가 중복 없이 작업하도록 한다.
- Scope: 전용 수집기·테스트·계획/실행 안내·분할 명단·휴대 가능한 재개 자료. 기존 수집 데이터와 운영 SQLite는 보존하며 사용자 대신 수집을 시작하지 않는다.
- Acceptance Criteria: 두 파트의 교집합은 공집합이고 합집합은 27,824건이다. 결과·상태 파일이 파트별로 구분되고 재개 자료의 완료/확인 필요 자료를 재요청하지 않는다. 단일 PC 중복 실행을 막고 서버 제한 대기·중단 정책을 유지한다. 변경 코드를 커밋하고 원격 반영을 확인한다.
- Tests: 기간 필터·기존 데이터 보존·분할 결정성/완전성·새 대기 범위와 재개·스냅샷 복원·접근 제한 보존을 검증하고 관련 회귀 테스트·Ruff·실제 분할 수/자료 수를 대조한다.
- Dependencies: 기존 수집기와 사용자의 2026-11-14 간격 변경·두 PC 분할·원격 반영 요청.

## 검증·인계 기록

- RED: 기존 대기 범위와 분할 함수 부재로 새 요구 테스트가 실패했다. GREEN: 분할 결정성·스냅샷 복원·중복 실행 방지와 후속 1차 구간 검증까지 전체 65개 테스트 통과. Ruff check/format·diff 검사 통과.
- 실제 대상은 Part 1 13,930건·Part 2 13,894건이며 교집합 없이 총 27,824건이다. 기존 1,790건의 내용과 판정 상태를 보존해 각 파트가 894건·896건을 가져가고, 남은 대상은 각각 13,036건·12,998건이다.
- 별도의 빈 운영 저장소에서도 공통 재개 자료를 읽어 같은 건수로 복원됨을 검증했다. 접근 제한 상태는 분할/복원으로 해제하지 않으며 기존 서버 대기 시각을 보존한다.
- 기존 통합 수집을 저장 후 멈췄고 새 파트 수집은 실행하지 않았다. 각 PC의 사용자가 `--part 1 --through-year 2016`·`--part 2 --through-year 2016`으로 직접 실행한다. 1차 우선 수집은 `TASK_DETAIL_PHASE_PRIORITY.md`에 기록한다.
- 책 소개·목차의 원문 공백을 보존하기 위해 해당 원자료 CSV에만 Git 공백 검사 제외 속성을 지정했다. 코드·테스트·문서는 기존 공백 검사를 유지했다.
